# NeuroTrace 演示脚本

## 演示前准备

1. 在项目目录运行 `python -m pytest -q`，确认全部测试通过。
2. 运行 `streamlit run app.py`。
3. 打开首页，点击一次“恢复演示”，确保三条审核状态均为 `pending`。
4. 浏览器保持普通笔记本宽度；不打开侧栏或其他后台页面。

## 3 分钟版本

### 0:00–0:30｜问题

“科研 AI 已经很会总结论文，但研究写作里更危险的错误往往不是编造，而是把真实论文写成范围过大的结论。这里有一句看起来很专业的话：支持性语境会跨隐喻类型稳定降低 N400。”

操作：指向预置论断，点击“编译证据边界”。

### 0:30–1:05｜编译边界

“NeuroTrace 不先替我写，而是把论断拆成研究对象、语境、隐喻类型、任务、ERP 成分、加工阶段和作用方向。结果是过度概括，风险包括绝对化、跨类型泛化、N400 方向错误、阶段遗漏和任务/情绪边界遗漏。”

操作：快速扫过红色结论和维度表。

### 1:05–2:05｜三篇论文的不同角色

“Tang 提供有条件支持，但只限科学隐喻、相关/无关语境和 SMF/SMS 差异。Yao 是直接限定：常规隐喻没有可靠语境效应；新颖隐喻反而是早期 N400 更大、后期整合更容易。Baiocco 很重要，但它检验的是任务和情绪性，不能当作支持性语境的直接证据。”

操作：依次展开 Tang、Yao、Baiocco；Tang 和 Yao 选 `approve`，Baiocco 选 `approve`，指出 Baiocco 仍锁定为 `boundary_evidence`。

### 2:05–3:00｜人工门控与导出

“只有人工通过的证据才进入 Evidence Pack。安全改写保留了真正能说的部分，也明确了常规性、任务、情绪和加工阶段。最后可以下载 Markdown、JSON、CSV，每条都带页码、图号、审核记录和 PDF 哈希。”

操作：展示安全改写，点击一个下载按钮。结尾强调：“它解决的不是上下文不够长，而是长上下文也不会自动保证引用边界正确。”

## 5 分钟版本

### 0:00–0:50｜开场与真实用户

“这是我自己在 ERP/EEG 隐喻研究中会遇到的问题。写综述时，大模型可以把每篇论文都总结对，却可能在最后一句话里把不同对象、条件和时间阶段合并成一个不存在的统一规律。”

展示预置英文论断，并口述中文含义。

### 0:50–1:35｜为什么普通长文本不够

“这里不是缺少文本。三篇论文都可以放进上下文。问题是模型必须判断每篇论文对这句话究竟是直接支持、条件性支持、限定，还是只能提供边界。这个判断如果没有显式结构和人工门控，很容易被流畅语言抹平。”

点击“编译证据边界”，介绍 7 个维度和 5 个风险。

### 1:35–3:20｜逐篇证据核验

- Tang：展示第 1、12、13 页和 Fig. 10、Fig. 11；说明相关语境可能促进，但无关语境会干扰，且 SMF/SMS 和加工阶段不同。选择 `approve`。
- Yao：展示第 1、8、9 页和 Fig. 4、Fig. 5；说明常规隐喻无显著语境效应，新颖隐喻是早期阻碍、后期促进。选择 `approve`。
- Baiocco：展示第 1、10 页和 Fig. 3、Fig. 5；说明它检验任务与情绪，不是支持性语境的直接测试。选择 `needs_fix`，先留空展示门控失败，再填写“仅作为任务与情绪性改变 ERP 模式的边界证据”，展示门控通过但角色未升级。

### 3:20–4:20｜安全改写

“原句写的是跨类型、稳定、单向。安全版本改成：语境可以调节隐喻加工，但方向和 ERP 表征取决于语境相关性、隐喻常规性、任务、情绪性和加工阶段。对 L2 新颖隐喻，支持性语境可能增加早期 N400 困难，却促进后期整合；常规隐喻可能没有可靠效应。”

指向页面上的三项范围变化。

### 4:20–5:00｜Evidence Pack 与结尾

依次指出 Markdown、JSON、CSV 下载；说明导出只包含通过人工审核的记录，保留修订值、审核时间、页码、图号和 SHA256。

“NeuroTrace 不是通用聊天机器人，也不声称解决所有科研写作。它先把一个真实、危险、可复现的问题做窄：在论断进入论文前，给现实补上一道证据边界防火墙。”

## 现场故障降级

- 无网络：不受影响，核心路径完全离线。
- PDF 路径未配置：界面显示 `missing`，但审计、人工门控和导出仍可演示；赛前应配置本地目录以展示 `verified`。
- 浏览器刷新：点击“恢复演示”回到一致状态。
- 下载受浏览器策略阻止：直接展示三个按钮并运行导出测试作为可复现证明。
