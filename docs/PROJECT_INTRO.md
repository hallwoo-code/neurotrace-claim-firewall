# NeuroTrace 项目介绍

## 项目定位

NeuroTrace 的副标题是“ERP/EEG 科研论断防火墙”，参赛赛道为 Challenge 01“为现实打个补丁”。它解决的不是论文读得不够多，而是论文中的真实发现被写成了越过证据边界的结论。

## 解决的问题

研究者准备写下“支持性语境会跨隐喻类型稳定促进隐喻理解，并体现为 N400 波幅降低”。这句话在语言上流畅，在证据上却把相关语境、支持性语境、常规隐喻、新颖隐喻、科学隐喻子类型、任务差异与加工阶段压缩到了一起。

长上下文只能让模型看到更多材料，不能自动建立“哪篇论文能支持到哪里”的引用边界。NeuroTrace 因此先编译论断，再允许写作。

## 目标用户与场景

目标用户是进行 ERP/EEG 隐喻加工研究、正在写综述或论文的研究者。典型场景发生在一句结论即将进入正文或综述表格之前：研究者把候选论断交给系统，核对三篇关键论文，人工决定证据是否可用，再导出可追溯的 Evidence Pack。

## 核心功能

1. 将候选论断拆为 population、context、metaphor type、task、ERP component、processing stage、effect direction。
2. 识别绝对化、跨类型泛化、N400 方向错误、加工阶段遗漏、任务/情绪边界遗漏。
3. 将三篇论文固定分类为条件性支持、直接限定/反例、非直接边界证据。
4. 通过 `approve`、`needs_fix`、`reject` 完成人工审核；未通过门控的记录不会进入导出包。
5. 输出安全改写及 Markdown、JSON、CSV Evidence Pack。
6. 通过 SHA256 证明三篇源 PDF 未被修改。

## 技术方案

- Python + Streamlit 单页应用；
- 标准库数据模型、规则审计、CSV/JSON/Markdown 导出；
- JSON 保存三条 claim-level evidence record；
- 不依赖在线模型或向量数据库；
- pytest 覆盖核心规则、门控、导出回读与完整性检查；
- 本地配置只保存 PDF 目录，且被 Git 忽略。

## 创新点

- 从“回答问题”转向“约束结论”：系统的核心输出是证据边界，而不是更流畅的摘要。
- 将证据角色与 directness 分开：一篇论文可以重要，但仍然不是候选论断的直接检验。
- 把人工审核做成导出门控，而不是装饰性确认。
- 用页码、图号、条件、时间窗、效应方向和源哈希构成可复核的最小证据单元。
- 离线确定性黄金路径适合现场演示和复现，不把成功寄托在网络或模型随机性上。

## 当前完成情况

黄金路径、三条证据、五类风险、人工门控、三种导出、SHA256 校验、自动测试、比赛文档和单页演示界面均已完成。当前范围严格保持为三篇论文与一条论断。

## 运行与演示入口

```powershell
python -m pytest -q
streamlit run app.py
```

默认浏览器入口为 `http://localhost:8501`。
